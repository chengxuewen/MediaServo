# 2026-08-21 docker-deployment-modes — Docker deployment form rework (single container + named volumes + prod reference)

**Status**: Plan pending review | **Scope correction**: the existing Dockerfile already has multi-stage (base/dev/builder/runtime + USER + HEALTHCHECK) — this plan focuses on the **gaps**: data volume normalization, prod reference orchestration, image slimming audit

---

## 1. Proposal

### What

Complete the standardization of MediaServo's Docker deployment form (modeled on the 3rdparty/AccessBase build engineering): ① **data volumes → named volumes** (retire bind-mount single files — root-cures C34 EBUSY; config templates initialized on first start) ② **prod compose reference sample** (single image + named volumes — isomorphic to AccessBase prod, a third-party integration deliverable) ③ **image slimming audit** (builder strip + runtime apt dependency pruning — shrink the 17GB image). Runtime form unchanged: **single all-in-one container** (server + SFU + embedded admin; no DB — YAGNI).

### Why

- C34 lesson: bind-mount single file (devices.yaml) rename = EBUSY — atomic write failed and had to fall back to direct write; inside a named volume it is a normal filesystem — atomic write restored
- Production/third-party integration lacks a reference orchestration (dev compose has a rough server+caddy shape — no prod single-image sample)
- Image is 17GB (system df Total — **dev toolchain image**; the `--target runtime` deliverable image is expected ~200-400MB) — strip and libssl3 audit (AccessBase runtime slimming as reference) — **the size baseline counts the runtime image only**

### Scope

**In scope**:
- compose volumes → named volumes (`mediaservo-data` → container `/opt/mediaservo/etc` + `mediaservo-recordings`)
- Startup initialization: config templates placed when a named volume is first mounted (entrypoint or server built-in fallback — server.yaml/accounts.yaml/devices.yaml generated by default)
- `docker-compose.prod.yml`: single image (`mediaservo-server:latest`) + named volumes + healthcheck + resource limits (isomorphic to AccessBase prod)
- Image slimming: builder release adds strip; runtime baseline = `--target runtime` (~200-400MB — the dev 9GB includes the toolchain and is not a deliverable)
- Verification matrix (size/build cache hits/functional regression — **all via the mediaservo.sh entry point**)
- **mediaservo.sh command surface rework** (user decision: no backward-compat burden — mainstream CLI design: up/down deployment lifecycle, --env global environment, e2e sub-suites, data domain, unified doctor)

**Out of scope**:
- Introducing a database (YAGNI — evolution path documented in 26-docker-deployment-modes.md)
- dev compose hot-reload mechanism (kept — source bind-mount + cargo-cache volume)
- Enabling the caddy proxy (kept disabled — optional)
- Dockerized frontend build (artifacts already embedded — unnecessary, see 26 doc)

### Risks

1. **Named volume initialization**: on first `docker run -v mediaservo-data` the volume is empty — **current state**: a missing server.yaml does not fail-fast (falls back to DEFAULT_SERVER_CONFIG — **a known hardcoded psk**); missing accounts/devices is tolerated (empty tables) — **the point of init = secret provisioning (eliminating the known default PSK) + persistence semantics**, not removing fail-fast; initialization priority: existing volume files > templates; **prod templates must never contain dev placeholders (I2 guard refuses to start)**; **entrypoint bootstrap guarantees server.yaml is always generated (exit 1 if missing — the container does not rely on the DEFAULT fallback — sec F6)**
2. **Config hot-reload regression**: dev compose moving from bind-mount to named volumes breaks "edit config → takes effect" (the volume does not share host files) — **dev compose keeps bind-mount** (named volumes only for production) — dual-track: dev file mounts + prod named volumes
3. **Slimming mis-deletes**: wrong apt package removal in runtime → missing runtime libs (libav/ssl) — the audit must cross-check ldd
4. **Device provisioning EBUSY regression**: under a named volume, rename-based atomic writes should be restored — the save() fallback logic stays (harmless safety net) — verification point

- [ ] dev compose behavior unchanged (bind-mount hot reload + cargo-cache volume)
- [ ] Image size: `--target runtime` baseline <400MB (after strip; the dev toolchain image is not a deliverable)
- [ ] Functional regression: e2e_sfu 4/4 + push_e2e 6/6 + admin Playwright (device provisioning spec) + build cache hit verification (source change does not re-pull dependencies)
- [ ] `docs/modules/26-docker-deployment-modes.md` written (design rationale) + memory captured

## 2. Design

### Architecture

```
Production (single container):
  docker run -v mediaservo-data:/opt/mediaservo/etc -v mediaservo-recordings:/opt/mediaservo/recordings \
    mediaservo-server:latest
  └─ entrypoint: empty volume → copy config templates (server.yaml/accounts.yaml/devices.yaml defaults)
                volume has data → use directly (persistence)
  └─ server: yaml loading (accounts/devices) → 9800 + SFU
       └─ Device provisioning: save() atomic write (normal file in named volume — rename OK — EBUSY fallback kept)

dev (unchanged): bind-mount config/ + cargo-cache volume (hot reload/debug unchanged)

Third-party reference (docker-compose.prod.yml):
  server: mediaservo-server:latest + volumes + healthcheck + resources
```

### Files to Touch

| Op | File | Purpose |
|----|------|---------|
| Modify | `docker-compose.dev.yml` | server volumes: devices.yaml mount kept (dev dual-track); **untouched** (bind-mount hot reload) — volumes comments only |
| Modify | `docker-compose.yml` (root — **already the prod single-image reference**, do not create a parallel one) | bind-mount → named volumes (mediaservo-data/recordings) + entrypoint semantics — single prod entry |
| Create | `entrypoint.sh` (in container) | Named volume initialization: missing templates → copy built-in templates (templates included in image at /opt/mediaservo/templates/) |
| Modify | `Dockerfile` (runtime stage) | ① COPY entrypoint + templates dir ② ENTRYPOINT (**replaces** the existing 169 lines — exec-form keeps PID-1) ③ `RUN mkdir -p /opt/mediaservo/{etc,recordings,templates} && chown -R mediaservo:` (before USER — named-volume copy-up preserves owner — root-cures empty-volume EACCES) ④ apt audit (ldd verifies libssl3) |
| Modify | `Dockerfile` (builder stage) | `strip` the binary after the release build (main lever for image slimming — same as the PIT-119 lesson) |
| Modify | `crates/mediaservo-server/src/main.rs` (if needed) | fallback semantics when server.yaml is missing (untouched if entrypoint covers it) |
| Modify | `scripts/mediaservo_cli.py` (argparse rework) | Target command surface: up/down/ps/logs/exec/e2e sub-suites/data/doctor/config set/--env global option (no compat burden — one-shot rewrite) |

### Data Flow

1. **First start (empty volume)**: `docker run -v mediaservo-data` → entrypoint detects `/opt/mediaservo/etc/server.yaml` missing → copies from `/opt/mediaservo/templates/*.yaml` (with dev placeholder accounts/empty device table) → exec server → 9800 ready
2. **Subsequent starts (volume has data)**: entrypoint skips the copy → server uses in-volume config (image upgrades do not overwrite config — persistence semantics)
3. **Device provisioning**: POST /devices → save() rename (normal file in named volume — **atomic write restored** — EBUSY fallback kept as safety net)

### Error Handling

- entrypoint copy failure (read-only volume/permissions): explicit stderr + exit 1 (C15 — never silent)
- Half-initialized volume (server.yaml present, accounts missing): per-file copy (check missing files one by one) — never overwrite the whole directory
- Image slimming: strip failure does not block (warn); cross-check `ldd /usr/local/bin/mediaservo-server` before apt removals (missed removal → runtime error — covered by the verification matrix)

### Testing Strategy

- Build: `docker compose -f docker-compose.prod.yml build` size comparison (before/after)
- Deploy smoke: empty-volume first start → config initialization → admin 200 → device provisioning (rename atomic-write verification — no EBUSY fallback in logs) → container recreation (volume kept — config/devices persist)
- dev regression: dev compose hot-reload behavior unchanged (config edits take effect)
- Functional: e2e_sfu 4/4 + push_e2e 6/6 + Playwright device provisioning spec
- Build cache: second `docker compose build` (no source change) cache hit (dependency layer not rebuilt)

### Dependencies

No new dependencies. Dockerfile/compose/entrypoint are pure build-surface changes.

## Phase 2: named volumes + entrypoint bootstrap initialization (team review C1/C2/C5/H8 absorbed)

- [ ] **entrypoint bootstrap (abandon env_file — at container creation compose resolves host-side and cannot read in-volume .env; signaling.rs defaults to allow when env is missing)**
  - File: `Dockerfile` (COPY entrypoint.sh + templates/) + `entrypoint.sh`
  - Content (the order is the security contract):
    ① `USER root` → entrypoint (root writes the volume) → at the end `exec su-exec mediaservo mediaservo-server` (privilege drop keeps PID-1 signals)
    ② **single-source secret generation** (generated once — accounts.rs fail-fast requires both secrets equal): random ≥32B → server.yaml `jwt_secret`+`admin_jwt_secret` **same value** written to the volume + PSK written to the volume `.env` (chmod 600) → `set -a; . .env; set +a` → **process env injection** (not compose env_file — closes the path where WS auth only reads env)
    ③ Templates: **prod = `accounts.production.yaml` (accounts:{}) + empty devices + server.yaml with no secret fields whatsoever** (never copy dev placeholders — I2 refuses to start); copy per missing file; **write .env first (atomic tmp+rename), then copy templates**; any missing/incomplete → exit 1, server does not start (first-start idempotency — ops H5)
    ④ **First-start admin bootstrap** (empty account table cannot log in — provisioning smoke reachability): `MEDIASERVO_ADMIN_PASSWORD` env creates the admin on first start (one-time stdout hint) or an `exec <svc> -- admin create` subcommand
    ⑤ Failure → exit 1 (C15)
  - Verify: empty-volume first start → configs generated (no dev placeholders) → **log `psk_set=true` (auth closed — not default-allow)** → admin 200 → login succeeds (bootstrap account) → second start does not overwrite; container restart keeps PSK stable (volume .env persists)
